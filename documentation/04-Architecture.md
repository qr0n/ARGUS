# ARGUS Documentation: Architecture Overview

This document provides a high-level overview of the technical architecture driving the ARGUS platform.

---

## 1. System Components

The ARGUS project is divided into two primary, decoupled components: the **Frontend** and the **Backend**.

### 1.1 Frontend (React / Vite)
- **Framework:** The user interface is built using React, bundled and served through Vite for fast hot-module replacement and optimized production builds.
- **Language:** TypeScript is used throughout to ensure type safety and code quality, alongside ESLint rules tailored for React DOM.
- **Pages / Routes:**
  | Route | Page | Description |
  |---|---|---|
  | `/` | Dashboard | System overview: active alerts, case count, module status |
  | `/live-camera` | Live Camera | Real-time video stream with face recognition overlay |
  | `/find-matches` | Find Matches | Upload a still image and scan it against the dataset |
  | `/ai-aging` | AI Aging | Simulate aging on an uploaded image, then match against dataset |
  | `/case-profiles` | Case Profiles | Add, view, and delete known face profiles |
  | `/alerts` | Alerts | Unreviewed high-severity event feed |
  | `/activity-log` | Activity Log | Full chronological log of all system events |
- **Dev Proxy:** The Vite development server proxies `/api`, `/dataset`, `/models`, `/ws-view`, and `/ws-stream` to the backend at `https://localhost:3000`, avoiding CORS and mixed-content issues during development.

### 1.2 Backend (Node.js / Express)
- **Server:** A Node.js + Express HTTPS server on port `3000` handles all API requests and serves static files. HTTPS is required for browsers to grant camera access (`navigator.mediaDevices.getUserMedia`).
- **WebSockets (`ws`):** A `WebSocketServer` attached to the HTTPS server relays frames and signaling between devices in real time:
  - `/ws-stream` — the streamer device (phone) connects here to push video data.
  - `/ws-view` (any other path) — viewer clients connect here to receive the stream and send WebRTC signaling back to the streamer.
- **File Storage:**
  - `/dataset` — stores known face profile images (`.jpg`, `.png`, `.jpeg`).
  - `/models` — stores the offline `face-api.js` model weight files, served statically to the browser.
  - `/public` — serves the standalone streamer (`stream-video.html`) and viewer (`view-stream.html`) HTML pages.
  - `dataset/logs.json` — a flat-file log store capped at 100 entries. Acts as a lightweight database for activity events, removing the need for a full relational database in initial deployments.
- **Security / HTTPS:** SSL certificates (`cert.pem` / `key.pem`) are auto-generated by running `npm run setup` in the backend directory. The server will refuse to start without them.

## 2. Face Recognition and AI Processing
- **AI Models:** The `face-api.js` library (TensorFlow.js-backed) is used for all face detection and recognition. Required model weight files are downloaded via `npm run setup` and served from the backend's `/models` route.
- **Execution:** Face recognition runs **entirely in the browser** on the viewer/client side (Live Camera, Find Matches, AI Aging). This eliminates server-side GPU requirements and keeps the backend lightweight. Bounding boxes and labels are drawn over the video element using an HTML5 Canvas overlay.
- **Models used:** `ssdMobilenetv1` (detection), `faceLandmark68Net` (landmarks), `faceRecognitionNet` (128-D descriptors).

---

## 3. Communication Flow

1. **Camera Initiation:** A streamer device opens a WebSocket to `/ws-stream` and begins pushing raw video frames or WebRTC signaling messages.
2. **Viewer Display:** A viewer client connects to `/ws-view`, receiving a `streamer-present` event. The feed begins rendering and face recognition inference starts on the viewer's browser.
3. **Bidirectional Relay:** The backend relays all messages between streamer and viewer(s) without interpreting the payload, keeping the server stateless with respect to video content.
4. **REST API:** All non-streaming interactions use standard HTTP endpoints:
   | Method | Endpoint | Description |
   |---|---|---|
   | `GET` | `/dataset` | List all profile image filenames |
   | `POST` | `/dataset/upload` | Upload a new profile image |
   | `DELETE` | `/dataset/:filename` | Remove a profile image |
   | `GET` | `/api/logs` | Retrieve all activity log entries |
   | `POST` | `/api/logs` | Create a new log entry |
   | `PATCH` | `/api/logs/:id/status` | Update the reviewed status of a log entry |
